# Google Authentication Documentation

## Overview

Esar Cars supports authentication using Google Identity Services.

Users can create accounts or login using their Google account without entering a password.

The system verifies the Google identity token, retrieves user information, then creates or links the user account.


---

# Google Authentication Flow


The complete flow:


```
Client

  |
  |
  ↓

Google Identity Services

  |
  |
  ↓

Google ID Token

  |
  |
  ↓

Esar Cars API

  |
  |
  ↓

Verify Token With Google

  |
  |
  ↓

Create / Find User

  |
  |
  ↓

Generate Authentication Token

  |
  |
  ↓

Authenticated User
```



---

# Endpoint


## Google Login


```
POST /api/v1/auth/google
```



Authentication:

```
Public
```



---

# Request


```json
{
    "id_token": "GOOGLE_ID_TOKEN"
}
```



The `id_token` is generated by Google Identity Services.



---

# Google Token Verification


The backend never trusts the token directly.

The API verifies the token first.


Process:


```
Receive ID Token

      |
      ↓

Send Token To Google Verification Service

      |
      ↓

Validate Token

      |
      ↓

Extract User Information
```



Extracted information:


```text
google_id

name

email

avatar
```



---

# User Creation Logic


After successful verification:


The system checks if the email already exists.


## Case 1: New Google User


If user does not exist:


A new account is created.



Example:


```text
name = Ahmed Mohamed

email = ahmed@gmail.com

google_id = 123456789

provider = google

status = active

email_verified_at = now()

has_password = false
```



Why?


Because Google already verified the email.



---

# Case 2: Existing Email Account


If a user already exists with the same email:


Example:


Before:


```text
email = ahmed@gmail.com

provider = null

has_password = true
```


After Google login:


```text
email = ahmed@gmail.com

provider = google

google_id = google_id_value
```



The account becomes linked with Google.



---

# Database Fields Explanation


## google_id


Column:


```
google_id
```


Purpose:


Stores Google's unique identifier for the user.


Example:


```
google_id = 1029384756
```



Why not use email?


Because:

- Email can change.
- Google ID is unique and permanent.



---

## provider


Column:


```
provider
```


Purpose:


Identifies authentication source.


Possible values:


```
google

null
```



Examples:


Normal user:


```
provider = null
```


Google user:


```
provider = google
```



---

## has_password


Column:


```
has_password
```


Purpose:


Determines if user can login using password.



Normal account:


```
has_password = true
```



Google-only account:


```
has_password = false
```



---

# Google User Password Flow


Google users are created without a password.



Initial state:


```
provider = google

has_password = false
```



The user can create a password using:


```
POST /api/set-password
```



After setting password:


```
provider = google

has_password = true
```



Now user can:


- Login using Google
- Login using password
- Change password
- Reset password



---

# Password Login Restriction


Google-only users cannot login using password.


Example:


User:


```
provider = google

has_password = false
```



Request:


```json
{
    "email":"google@gmail.com",
    "password":"12345678"
}
```



Response:


```json
{
    "success":false,
    "message":"This account uses Google login, please sign in with Google."
}
```



---

# Google Authentication Security


Implemented security measures:


## Token Verification


The backend verifies Google ID Token before creating session.


---

## Email Verification


Google users automatically receive:


```
email_verified_at = now()
```


because Google already verified the email.



---

## No Plain Password Storage


Google users receive a generated random password internally.


Example:


```php
Str::random(32)
```



The user never knows this password.



---

# Google Login Response


Successful login:


```json
{
    "success":true,
    "message":"Google login successful",
    "data":{
        "user":{
            "id":1,
            "name":"Ahmed",
            "email":"ahmed@gmail.com",
            "provider":"google"
        }
    }
}
```



---

# Error Handling


## Invalid Google Token


Response:


```json
{
    "success":false,
    "message":"Invalid Google token"
}
```



---

## Email Conflict


When Google email conflicts with an existing account:


The system links the account instead of creating duplicate users.
